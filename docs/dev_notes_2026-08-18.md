# 开发问题记录（2026-08-18）

> 记录今天开发过程中遇到的问题、根因与解决方案，供后续参考避免重蹈覆辙。

## 1. 标定相关问题

### 1.1 对侧点配对法无法标定 lidar_tilt.yaw

**现象**：`_symmetry_residuals` 用 θ 与 θ+180° 最近邻配对，代价函数对 `lidar_tilt.yaw` 完全不敏感（所有角度代价相同）。

**根因**：早期校正模型错误。当时写的是 `p @ r_theta @ r_lidar`，旋转不改变距离，导致 yaw 无论如何变化代价都不变。

**解决**：改用正确的校正模型 `p @ Rz(θ) @ m.T @ R_lidar @ m @ R_tilt @ Rz(θ).T @ R_tilt.T`（见 `docs/coordinate_transform_spec.md`），yaw 才变得可观。

**教训**：校正公式必须先验证"参数变化 → 代价变化"，再开始优化。写标定代码前先推导物理模型。

### 1.2 calibrate_planar.py 校正公式错误

**现象**：`calibrate_planar.py::apply_correction` 写的是 `pt @ r_theta @ r_tilt @ r_theta.T @ r_lidar`，缺少 `m.T @ R_lidar @ m` 包裹，且旋转顺序错误。

**根因**：没有与 `joint_tilt_calibration.py` 的公式对齐，lidar 校正直接作用在世界系而非雷达系。

**解决**：统一为 `p @ Rz(θ) @ m.T @ R_lidar @ m @ R_tilt @ Rz(θ).T @ R_tilt.T`。

**状态**：❌ 尚未修复（见 `docs/coordinate_transform_spec.md` 第 3 节）。

### 1.3 标定结果撞边界（±10°）

**现象**：联合优化 6 参数（tilt 3 + lidar 3）时，roll/pitch/yaw 跑到边界。

**根因**：
- `lidar_tilt.roll` 在横装下等价于全局偏航，单次 360° 扫描**不可观**。
- `lidar_tilt.pitch` 与 `tilt.pitch` 强耦合。

**解决**：只标定可观参数：`tilt.roll/pitch` + `lidar_tilt.yaw`，roll/pitch 固定为 0。

### 1.4 标定脚本对侧点配对失败（找到 0 对）

**现象**：完整 360° 扫描（177 万点）后 `calibrate_planar` 找到 0 对对侧点。

**根因**：配对阈值 0.5m 过严 + 扫描数据本身有舵机未到位问题（见 §2）。

**教训**：先保证数据质量，再调算法参数。

## 2. 扫描数据质量问题

### 2.1 每帧点数差异巨大（842 ~ 2877）

**现象**：10Hz 下每帧点数两极分化：375 帧 2500-3000 点，289 帧 1000-2000 点。

**根因**：**舵机未到位就采集**。`SERVO_INTERVAL=0.1s`，但舵机指令 `T2000`（2 秒才能到位），
0.1 秒后采集时舵机还在移动中，帧数据不完整。

**解决**：
- 归位（home）保持 `T2000` + 等待 3s。
- step 移动的 T 值 = `interval * 1000 - 200`（留 200ms 余量），最小值 100ms。
- 移动后 sleep = `move_time/1000 + interval`（移动时间 + 采集等待时间）。

**教训**：硬件指令参数（T）与程序等待时间（interval）必须匹配，写死 T2000 而 interval=0.1 是典型 bug。

### 2.2 UDP 缓冲区残留旧数据

**现象**：即使等待时间正确，每帧点数仍忽高忽低。

**根因**：舵机移动期间雷达持续发包，UDP 缓冲区积累了旧角度数据；
`receive_scan()` 会把旧包和新包混在一起，导致帧内容混杂。

**解决**：在 `receive_scan()` 前调用 `lidar.clear_buffer()` 清空 UDP 缓冲区。

### 2.3 points_per_frame 上限截断

**现象**：雷达 10Hz 时每帧约 2600-2700 点，但曾担心 4000 不够、改到 20000 浪费内存。

**实测**：10Hz 下每帧最大 2877 点，**4000 足够**（留 50% 余量）。

**教训**：先实测再调参数，不要凭猜测改大缓冲（内存浪费）。

## 3. 代码/环境问题

### 3.1 scipy Rotation.mean() 使用错误

**现象**：`Rotation.mean(rotations_list)` 报 `AttributeError: 'list' object has no attribute '_backend'`。

**根因**：`Rotation.mean` 是实例方法，不是类方法；且它期望 Rotation 对象数组而非列表。

**解决**：手动四元数平均：收集所有四元数 → `np.mean` → 归一化 → `Rotation.from_quat`。

### 3.2 UnboundLocalError: world_frame_added referenced before assignment

**现象**：嵌套函数 `process_frame` 内修改外部变量 `world_frame_added` 报错。

**根因**：Python 嵌套作用域规则——函数内赋值会使变量变为局部变量，需显式声明。

**解决**：`nonlocal total_points, pcd, world_frame_added, lidar_frame_added`。

### 3.3 matplotlib 中文字体缺失

**现象**：`UserWarning: Glyph 28857 missing from font(s) DejaVu Sans Mono`。

**根因**：matplotlib 默认字体不含中文字形。

**解决**：界面文本改用英文（`Angle/Points/Progress`）。

### 3.4 InfoOverlay 中 plt 未定义

**现象**：`NameError: name 'plt' is not defined`。

**根因**：`plt` 只在 `_init_window` 内局部导入，`update` 方法中不可见。

**解决**：把 `plt` 保存为实例属性 `self.plt`。后因功能无用，整个 InfoOverlay 已删除。

### 3.5 open3d 未安装

**现象**：`ModuleNotFoundError: No module named 'open3d'`。

**根因**：当前激活环境是 `ros_humble`，open3d 装在 `drill_rod_scanner` 环境。

**解决**：用 `conda run -n ros_humble python ...` 运行（该环境有 open3d 0.19.0）。

## 4. Open3D 可视化问题

### 4.1 坐标系累积旋转（转太快）

**现象**：雷达坐标系越转越快。

**根因**：`mesh.rotate(R)` 是**累积**旋转（在当前姿态上再转），不是设置绝对姿态。

**解决**：保存初始顶点 `lidar_frame_init_vertices`，每次先恢复初始顶点，再用
`transform(绝对变换矩阵)` 设置新姿态。

### 4.2 坐标系影响包围盒导致缩放看不到全貌

**现象**：添加坐标系后视角缩放异常，点云看不到全貌。

**根因**：坐标系几何体在 add 时参与了包围盒计算（reset_bounding_box 默认 True）。

**解决**：坐标系延迟到第一帧点云后添加，并传 `reset_bounding_box=False`。

### 4.3 雷达坐标系画法错误

**现象**：画出的雷达 XYZ 轴方向不对（用 coordinate_frame 或错误变换）。

**根因**：把 `mount`（棱镜相位）混进了坐标轴变换，且用了 `.rotate()` 累积旋转。

**正确画法**（用户确认）：
- 雷达轴方向 = `to_world_matrix()` 的三行（雷达x→世界-z、雷达y→世界y、雷达z→世界x）。
- 再乘以舵机旋转 `Rz(θ).T`。
- **只用 to_world，不用 mount**（mount 是扫描数据相位，不改变物理安装方向）。
- 用 LineSet 手动画三条轴（X=红、Y=绿、Z=蓝）。

## 5. 概念澄清

### 5.1 mount vs to_world 的区别

- `mount`：**棱镜 0° 参考相位**，绕雷达系轴旋转**扫描数据点**，对齐出厂 0° 参考。不影响物理安装方向。
- `to_world`：**安装姿态**，定义雷达三轴在世界系中的**物理指向**（轴映射）。

### 5.2 行向量变换从左往右读

`p @ A @ B @ C`：先应用 A，再 B，再 C（**从左往右**）。
点从雷达系出发：修自身偏差（lidar_tilt、mount）→ 换世界系（to_world）→ 叠加转盘运动（旋转+倾斜）。

### 5.3 每帧点数与雷达频率

- 10Hz：每帧约 2600-2700 点（每帧时间长，点数多）。
- 30Hz：每帧点数少。
- 用户实际经验：10Hz 每帧点数密度更高，不是 30Hz。
